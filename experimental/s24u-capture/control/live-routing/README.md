# Opt-in same-boot live routing reference

**Developer source only. Not a flashable module, default installer, universal deployment, root/bootstrap tool, or reboot-persistence mechanism.** This directory is excluded from normal Clarifae module archives. Never copy it onto another firmware/boot and run Apply. No initializer or original vendor XML template is supplied.

The reference models one audited ARM64 SM-S928B/pineapple firmware and the existing experimental engine/capture bridge. It rewrites only Clarifae OUTPUT applies in three individually pinned XML views, then requests a targeted vendor.audio-hal restart when needed. It does not change microphone targets, model policy, stock capture effects or stock output effects. Music is an explicit opt-in; a speech denoiser may alter or suppress music. Empty output selection is supported.

## Files and prerequisites

- live-targets.sh: root/init-mount-namespace, same-kernel-boot routing transaction with immutable RAM generations, owned mount/hash checks, serialization, bounded action/guard and rollback journal.
- render-targets.awk: deliberately narrow renderer for the independently audited line-oriented XML format. Unsupported compact/ambiguous layout, duplicate stream blocks, malformed/duplicate targets and ambiguous Clarifae applies fail closed. It is not a general XML parser.
- integration/: clearly separate optional source copies of app.js, kernelsu.js, index.html, clarifae-ctl and functions.sh, derived from portable PR4 commit182d8cf54d76f44e4437e0435566c9c1a99c3aec. Only these copies add vendor-readable property aliases, a mandatory manager hook and live-routing-specific feedback. Existing upstream UI styles/assets are not duplicated. Nothing copies/installs them automatically. They supersede the older standalone vendor-property-mirror.patch for this integration; do not apply both blindly.
- tests/: self-contained synthetic XML plus mocked mount/service/property/DOM tests. No vendor templates, phone dumps or actual mount metadata are included.

The optional copies correspond to upstream webroot/{app.js,kernelsu.js,index.html} and common/{clarifae-ctl,functions.sh}. They are review inputs, not a drop-in installer. An audited deployer must reconcile the stated portable base, existing assets, preferred CLI/helper copies and every startup/control writer together; this tree does not perform those writes.

The literal Android root path and engine/bridge hashes in the script are reference contract pins, not private transport details. They must match the independently verified deployed runtime; changing a string is not compatibility proof. Public production pins remain engine64ebebbfe8f62ed7a6c7f43cc558e710e916509dad9148191f9eec4f315811e9 and bridge5b889b6abed6b4fa73c28b1bf2c78983d69fc9f3f245e279b0badfbc94c671b6. The engine/capture implementation itself is unchanged by this UI follow-up.

An **audited deployer**, not this source tree, must initialize all of the following from a fresh, recoverable, same-boot baseline:

1. Root-owned, non-symlink and non-group/world-writable manager/base/state/RAM paths. The RAM path must be the recorded tmpfs in init namespace, not a persistent directory. Required Android tools, exact HAL/ABI/loader behavior, stock preservation and independent rollback must already be established.
2. The current kernel boot ID, plus exactly three manifest rows named generic, sku and sec. Their target paths are explicitly allowlisted in the script. Each row has the form name|audited-target-path|SHA256-of-owned-baseline-XML. No actual device manifest is provided here.
3. Private baseline XML files, their current owned top mount IDs and SELinux contexts under base/. These are the preceding audited view, which can already include a separately owned repair guard, not permission to remove unrelated mounts or expose stock partitions.
4. An immutable root-owned RAM generation named g- followed by a safe alphanumeric/hyphen suffix, containing each XML, hash-name files and the effective targets record. state/current points at that canonical generation, state/managed is0 or1, and state/mount-name files record exact current top IDs. All bytes, mount ownership and template format must be independently reconciled before any action.
5. Every normal WebUI/CLI writer and property sync path must be updated together for vendor-readable aliases. The optional integration refuses missing/uninitialized manager state; it does not silently fall back to an unsafe general audio restart or claim that saving a checkbox rewrites XML.

An uninitialized tree, missing RAM, changed boot, wrong runtime hashes, unsupported manifest or untrusted metadata is refused. There is no automatic initialization, re-rooting, boot service, mount-stack cleanup, force/lazy unmount or SELinux change. After a full reboot, inspect root/runtime/mount state afresh; persisted settings alone do not establish active processing.

## Transaction and recovery contract

Apply is a no-op without restart if the effective XML is already current. Explicit Restart still rebuilds/checks the selected routes before the targeted service restart. Active communication mode, active recording, missing/malformed monitor sections or unverifiable state refuse an interrupting action. Services and resulting hashes/IDs are checked before commit; a selection changed during the action aborts instead of committing a stale selection.

A global operation lock and atomic commit-versus-rollback decision are combined with a **shared mutation mutex** and a per-transaction atomic single-finalizer latch, so foreground/watchdog double release cannot delete a successor operation’s lock. The detached setsid/nohup watcher must acknowledge readiness before any mutation, and validates a terminal commit before foreground reports success. A decision directory alone is not a completed commit. A losing recovery claim returns failure, never a successful rollback; lock release independently requires proven terminal commit/rollback metadata. A rollback winner waits for an already-started forward mount/reload to quiesce; a late forward transaction cannot race rollback and then commit. The public Apply/Restart entry requests a45s userspace timeout; the internal worker has an explicit bounded-entry marker and is not a public API/security boundary against root. The guard deadline is75s before recovery; reload waits at most18s, mutating command wrappers8s each, and guard mutex acquisition8s. Recovery adds its own bounded steps; these are not an absolute kernel-level cancellation or whole-recovery wall-time guarantee.

A stuck/killed owner holding that mutex, timeout/signal/unknown mutator completion, an unjournaled/unowned mount, an incomplete decision, unavailable metadata or failed recovery is **rollback-blocked**, not falsely restored. SIGKILL/stuck-owner recovery is explicitly NOT automatic. Mutation intents with expected prior mount/source digest are journaled before every bind/unmount, and failed-bind observations are recorded. A bind that succeeds before its owned-ID journal write can remain ambiguous: it is never adopted by hash alone; lock/journal are retained for audited recovery. The lock/journal remain for audited operator recovery, and subsequent operations refuse to proceed. The guard never steals a held mutex or force-unmounts; this deliberately favors explicit blocking over a dangerous rollback race. Recovery may restore XML but defer service reload if a call/recording starts. No shell gate can eliminate every physical race with a new call starting immediately afterward; this is not an Android telephony-lock integration or a guarantee of uninterrupted calls.

## Source divergence from earlier device evidence

This public reference is **not byte-identical to the earlier installed manager**. Review repaired conditional-shell failure propagation and the double-global-lock release race; added guard-ready/terminal handshakes, mutation intents/child pins, a shared mutation mutex and single-finalizer latch; separated immutable environment checks from potentially corrupt committed metadata during recovery; and added validated hashes/snapshot members plus fdinfo-based visible mount IDs. A single strict AWK state machine rejects unknown/incomplete recording rows and removes raw gate dumps. Settings are read from one coherent config copy. The renderer rejects ambiguous formatting/duplicate streams, and unpublished no-op generations are removed. Those changes were tested only with host mocks here, not installed/retested on a phone. An integrator must reconcile them before considering activation; previous device evidence must not certify the new manager bytes.

Previously recorded single-device evidence for the earlier implementation:192 XML semantic cases,22 mocked transaction checks and11 mocked DOM/root-bridge checks; live preferred-control Apply rebuilt three XML views, deselect-all remained empty and removed applies, re-enable/idempotent Apply succeeded. One automatic-media session, without manually creating AudioEffect or Visualizer, reported actual DeepFilterNet mode3,123,840 successful frames, nonzero input/output peak0.00825772 and0 track underruns. These are native processing/timeline observations, not calibrated acoustics, music quality, gap-free delivery or cellular/modem certification. No personal tuning/configuration or private route dump is published.

The new public synthetic fixture suite separately covers192 cases across three minimal fake-stock XMLs, negative renderer cases, transaction failures and guard races, plus explicit fail-closed helper tests. The final host suite observes192 semantic +11 negative renderer cases,30 mocked transaction checks with the actual watcher state machine,61 safety-helper cases (including injected lost-claim and successor-lock races),14 optional-control cases and57 UI cases. A negative-control copy restoring the old successful-losing-claim behavior fails the intended regression. These counts are separate from the earlier22/11 device-source fixtures. The optional UI test uses mocked DOM/root bridge only. No new device access, restart, call or recording was used to publish this source.

## Host reproduction

From this directory, with Python3, Bash, awk and the usual POSIX tools (plus Node for the UI mock):

    python3 tests/test_renderer.py
    python3 tests/test_transactions.py
    python3 tests/test_safety.py
    python3 tests/test_integration.py
    node --test tests/test_ui.cjs

The transaction harness runs the actual watcher/decision state machine while replacing Android runtime/metadata/mount/service operations with temporary-file mocks. Safety helpers separately exercise conditional failures, strict audio parsing, terminal acknowledgements, mutex arbitration and a deterministic double-release/successor-lock race. Distinct committed generations and transaction journals are deliberately retained; finite RAM/journal capacity and audited retention remain operational limits. “Verified” means owned init-namespace XML/hash/ID plus service-property readback, not HAL namespace visibility, effect attachment or usable PCM. Passing mocks do not certify toybox/bionic/SELinux, firmware parser layout, real mounts, physical rollback or call safety. Do not execute live-targets.sh itself on a desktop.

The512KB effect-budget/concurrency limit and DeepFilterNet soft-realtime deadline overruns remain. USB/MMAP/offload, other firmware, cellular processing, broad Bluetooth routing, perceptual quality and cold-boot/reactivation remain uncertified. No normal installer/model/music defaults are changed by this reference.
